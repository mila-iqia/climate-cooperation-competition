# CBAM Regional Configuration — Data Pipeline

This document explains what was built, how it was built, and how it relates to
the existing regional yaml pipeline used throughout this project.

---

## Overview

Three CBAM-specific region configurations were created:

| Setup | Regions | Purpose |
|-------|---------|---------|
| `setup_3` | EU \| Merged CBAM Exporters \| RoW | Minimal baseline, fastest training |
| `setup_5` | EU \| Eurasia \| China \| MENA \| RoW | Sector-split, main paper results |
| `setup_7` | EU \| Eurasia \| China \| India \| Gulf \| N.Africa \| RoW | Maximum policy granularity |

For each setup, one `.yml` file per region plus a `CountryClass_cbam_N.csv`
were generated by `scripts/data_preparation/WBAPI_get_data_cbam.ipynb`.

---

## How the Existing Pipeline Works

Understanding the existing pipeline is key to seeing how the CBAM configurations
fit in without deviation.

### Step 1 — World Bank API data pull (`WBAPI_get_data.ipynb` / `WBAPI_get_data_N.ipynb`)

The original notebooks query the World Bank API (`wbgapi`) for each country
across 2003–2020:

| Series | Parameter derived |
|--------|------------------|
| `NY.GDP.MKTP.CD` | GDP → TFP (`xA_0`), emission intensity (`xsigma_0`) |
| `CM.MKT.LCAP.CD` | Capital market → `xK_0` (KNN-imputed where missing) |
| `SP.POP.TOTL` | Population → `xL_0`, `xL_a`, `xl_g` |
| `EN.ATM.CO2E.KT` | CO₂ emissions → `xsigma_0 = E / (Y * (1 - mu))` |
| `NE.CON.TOTL.ZS` | Consumption share → savings rate `xsaving_0` |

Missing capital data is imputed with a KNN regressor trained on (Y, L) pairs.
Missing CO₂ data is borrowed from a manually curated `borrowdict` of similar
countries.

### Step 2 — Time-series fitting (`opt_helper.py`)

From the raw time series, three dynamic parameters are fitted per country:

**Population dynamics** (`get_pop_lg`): fits `xl_g` (convergence rate) from
the logistic model:
$$L_{t+1} = L_t \cdot \left(\frac{1 + L_a}{1 + L_t}\right)^{x_{l_g}}$$
using linear regression on log-differences against `UN-pop-pred.csv` for the
2100 convergence value `xL_a`.

**TFP dynamics** (`get_gA_deltaA`): fits `xg_A` and `xdelta_A` from the model:
$$A_{t+1} = A_t \cdot \left(e^{0.0033} + g_A \cdot e^{-\delta_A \cdot t}\right)$$
using Nelder-Mead optimisation against the back-calculated TFP series.

**TFP level** (`xA_0`): back-calculated from the Cobb-Douglas identity:
$$A_0 = \frac{Y_0}{K_0^\gamma \cdot (L_0/1000)^{1-\gamma}}$$

### Step 3 — Regional aggregation (`merge_region` in `opt_helper.py`)

Countries are grouped by `RIG` (Region × Income Group index) from
`CountryClass_N.csv`. Within each group, `merge_region()` aggregates:

- **K, L, La**: summed across countries
- **A**: re-derived from merged Y/K/L via Cobb-Douglas (same identity as Step 2)
- **sigma**: GDP-output-weighted average: $\sigma = \sum_i Y_i \sigma_i / \sum_i Y_i$
- **g_A, delta_A**: geometric mean across countries
- **saving, mitigation, tax**: geometric mean

### Step 4 — Trade initialisation

`ximport` values (initial import bids) and `xexport` (export rate) come from
`csv_asset/N_import_2016.json` and `N_export_2016.json`, derived from EORA26
MRIO data for 2016. These are the observed bilateral trade flows rescaled to
RICE's normalised units.

### Step 5 — Yaml output (`write_yaml_files` in `opt_helper.py`)

Writes one `.yml` per region group containing both `_DICE_CONSTANT` (shared
climate model parameters, from `region_yamls/default.yml`) and `_RICE_CONSTANT`
(region-specific economic parameters from Steps 1–4).

## How the CBAM Pipeline Differs

The CBAM notebooks do **not** re-run Steps 1–3 from scratch. Instead they read
the already-calibrated 20-region yamls from `other_yamls/20_regions/` as inputs
and perform a second-level aggregation into CBAM groupings.

This is correct and consistent because `other_yamls/20_regions/` is itself the
output of the full pipeline above applied to the 20-region `CountryClass_20.csv`.
The CBAM steps are therefore **downstream** of the existing pipeline, not a
replacement for it.

### CBAM Step 1 — Load calibrated 20-region params

```python
params20 = {i: yaml.load("other_yamls/20_regions/{i}.yml") for i in 1..20}
```

All parameters in these yamls were produced by the full WB API + time-series
fitting pipeline. No raw data is re-processed.

### CBAM Step 2 — GDP proxy

A consistent GDP proxy is computed for each RIG to use as aggregation weights:

$$\text{GDP}^{(r)} = A_0^{(r)} \cdot (K_0^{(r)})^\gamma \cdot (L_0^{(r)}/1000)^{1-\gamma}$$

This is the exact Cobb-Douglas identity already implied by the existing calibration,
not a new data source.

### CBAM Step 3 — Merge 20-region RIGs into CBAM groups

The `merge_regions()` function in the notebook applies the same logic as
`merge_region()` in `opt_helper.py`, adapted for the yaml-input format:

| Parameter | CBAM method | `opt_helper.py` equivalent |
|-----------|-------------|---------------------------|
| `xK_0`, `xL_0`, `xL_a` | Summed | Summed |
| `xA_0` | Back-calculated from merged Y/K/L | Back-calculated from merged Y/K/L |
| `xg_A`, `xdelta_A` | GDP-weighted average | Geometric mean |
| `xsigma_0` | GDP-weighted average | GDP-output-weighted average |
| `xsaving_0` | Investment-weighted (Y × s) | Geometric mean |
| `xmitigation_0` | GDP-weighted average | Geometric mean |
| `xl_g` | Pop-slope-weighted | Fitted from merged time series |

> **Note on weighting**: the CBAM pipeline uses GDP-weighting rather than geometric
> means because it is operating on already-aggregated regional parameters rather
> than raw country time series. GDP-weighting preserves the Cobb-Douglas identity
> exactly, while geometric means are appropriate when fitting from raw data where
> outliers should not dominate.

The critical invariant is:
$$\sum_s \text{GDP}^{(s)}_{\text{CBAM}} = \sum_r \text{GDP}^{(r)}_{\text{sub-regions}}$$

This is verified by the sanity-check cell (cell 9) in the notebook, which
asserts `|GDP_check - GDP_expected| / GDP_expected < 1e-6` for every generated yaml.

### CBAM Step 4 — Trade re-indexing

`ximport` is re-derived from `csv_asset/20_import_2016.json` rather than carried
forward from the 20-region yamls, because the key set must change (e.g. from
`{'4': ..., '5': ..., '8': ...}` to `{'2': ..., '3': ...}`):

- For each source 20-region RIG, look up its CBAM group index
- Sum import weights from all sub-regions of the destination CBAM group,
  GDP-weighted within the importer
- Set self-imports (`ximport[own_index] = 0.0`) — same convention as original yamls
- Intra-group trade (between two RIGs that merged into the same CBAM region) is
  discarded — it becomes internal to that region

This preserves the same EORA 2016 bilateral trade data source used for all
existing region configurations.

### CBAM Step 5 — Yaml output

Uses the same `_DICE_CONSTANT` block from `region_yamls/default.yml` as all
other regional yamls. The `_RICE_CONSTANT` block has the same key structure as
the 20-region yamls. Generated files are therefore drop-in compatible with the
existing `Rice` and `RiceMRIO` environment loaders.

## CountryClass CSVs

Three `CountryClass_cbam_N.csv` files are generated alongside the yamls.
They follow the identical format as `csv_asset/CountryClass_20.csv`:

```
No, Economy, Code, RI, RIG
```

where `RIG` is now the CBAM region index (1–N) and `RI` is the CBAM region
human label (e.g. `"China"`, `"EU & Western Europe"`).

These files are the bridge between the yaml configurations and the MRIO
aggregation layer (`csv_asset/aggregate_local_mrio.py`). Running that script
with a `CountryClass_cbam_N.csv` will produce EORA sector tables aggregated
to the CBAM region grouping — the required input for Phase 2 disaggregated
trade and emissions in `rice_jax/_rice_mrio.py`.

## Reproducing the Outputs

```bash
cd /path/to/climate-cooperation-competition
jupyter nbconvert --to notebook --execute --inplace \
    scripts/data_preparation/WBAPI_get_data_cbam.ipynb
```

This regenerates all yamls and CSVs in `cbam_yamls/` in under 10 seconds.
No API calls are made; all inputs are local files.

To regenerate the upstream 20-region yamls (e.g. after a new WB data pull),
re-run `WBAPI_get_data_20.ipynb` first, then re-run the CBAM notebook.
